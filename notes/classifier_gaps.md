# Classifier v3 suspected gaps (for the future journal version; v3 is frozen in this paper)

Do not act on these in the IPTC-25544-MS rerun.

1. **Non-ASCII characters not normalised.** `normalise_text` replaces only ½, ¼, ¾, ⅛. The narratives (sum24Hr plus forecast24hr) also contain ³ (31), Ø (13), æ (9), ¿ (3), Æ (2), Å (1). `³` appears in volume units; `Ø` is used as a diameter or "at" symbol (e.g. `Ø 3100M`, `TD Ø 3220 M`) and may hide depth or hole-size context; `¿` (3) looks like a corrupted character in the source. Source: Stage 3 Unicode survey, `outputs/stage3_unicode_survey.csv`.
2. **The "8½" pattern in "Reservoir drilling" (`8½.{0,5}(?:hole|section)`) can never match after normalisation**, because ½ is replaced by " 1/2" first. **Confirmed in Stage 4:** the pattern matches 0 of 1,759 normalised narratives, so it is dead code. It does no harm because the same sizes are caught by `8.{0,3}1.2.{0,5}(?:hole|section|BHA)` after normalisation (19 narratives contain a literal `8½` followed by hole/section; their phase assignments are unchanged because Table 2 reproduces exactly).

3. **Future (journal version, not part of this rerun):** Independent kick-off check from directional survey files, if present in the Volve archive.

4. **Sequence-aware classification (journal version).** The classifier reads one report at a time. An engineer assigns a day using the neighbouring reports and the state of the campaign (which section is being drilled, whether casing is run or a sidetrack is under way). The external review asked for a context audit (five reports per sampled day, `src/stage6_context_audit.py`) to measure how often the neighbours decide the phase. Candidate design: carry the campaign state forward (last hole size, last casing run, sidetrack under way) and use it to resolve days that name no size or mix operations.
5. **Phases that the audit suggests are missing.** To be filled from the "Other (write in note)" entries and the unmatched ties of the context audit once the author returns the workbook. No phase is added to v3.
6. **Workover rule and whipstock or window milling.** The single-report blind audit found disagreements where whipstock or window milling in a sidetrack is classified as Workover. A sidetrack operation of this kind belongs to well construction, and the Workover patterns do not distinguish it from intervention work. Candidate rule: treat whipstock, window milling and sidetrack-window language as its own phase, or route it by context.
7. **Incidental-keyword triggers.** A keyword that appears in passing (for example a casing size or a cement term in a sentence about another operation) assigns a day to the phase of that keyword, because the priority order takes the first pattern that matches anywhere in the text. Candidate fix: score the whole narrative, weight the first operations named, or require the keyword in an operation clause.
