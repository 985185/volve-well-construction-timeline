# CLAUDE.md: Volve well construction timeline, clean rerun (IPTC-25544-MS)

## What this repo is

The reproducible pipeline behind the IPTC 2027 paper "Field-Scale Well Construction Timeline Reconstruction from WITSML Daily Drilling Reports" (T. Appalla, independent researcher). The paper reconstructs day-by-day construction phases for every Volve wellbore from WITSML Daily Drilling Reports (DDRs), audits what the classifier misses, and validates total depth and spud date against the Norwegian Offshore Directorate (NOD) FactPages.

This is a **one-time clean rerun from raw data**. Its purpose is that every number in the manuscript is regenerated by code in this repo and traceable to `outputs/numbers_registry.json`. Manuscript deadline 4 Jan 2027; target completion before 11 Dec 2026.

## Hard rules

1. **No invented numbers.** Every figure comes from code run in this session against files in `data/`. If you can't compute something, say so and stop.
2. **Stop and report on any discrepancy.** When a computed value differs from the v2 target in the table below, stop. Show the old value, the new value, the arithmetic, and the likely cause, then wait for TJ. The rerun value wins only after TJ confirms.
3. **Show arithmetic** for every derived figure in the stage report.
4. **Agree architecture before code.** At the start of each stage, state the plan in a few lines and wait for "go".
5. **Classifier v3 is frozen.** Port it verbatim from `inputs/`. Do not add, remove or edit a pattern, even an obvious fix. Log suspected gaps in `notes/classifier_gaps.md` for the future journal version.
6. **You never adjudicate audit records.** You prepare the workbook; TJ fills it in. Never write values into the adjudication columns.
7. **Raw data is read-only.** Nothing in `data/raw/` is modified after Stage 1. Record a SHA-256 for every raw file.
8. **No em dashes** in any prose you write (reports, README, manuscript text). Use commas, colons, or restructure.
9. **Secrets stay out of git.** Databricks auth comes from `~/.databrickscfg` profile `volve`. Never print or commit tokens.
10. When a task needs TJ to run something elsewhere (Claude Desktop, the IPTC portal), give him the exact command or prompt, not a description.

## Stages (each ends with reports/STAGE_n.md and a pause for TJ)

**0. Access check.** Check that Databricks auth works, that the volume lists, and that one DDR XML file downloads. Find all DDR XML files through the metadata catalog and count them. Confirm `inputs/` contents against STOCKTAKE.md section C, and list what's missing. Propose the architecture. *No code beyond the checks.*

**1. Fetch raw.** Download every DDR XML to `data/raw/ddr_xml/`, write `manifest.csv`, and download the NOD snapshot. Report file count and total bytes.

**2. Extract.** Parse WITSML 1.4.1.1 DDRs to `data/interim/ddr.parquet`: filename, well, wellbore, date_report, dTimSpud, md, md_kickoff, md_csg_last, rig, operator, forecast24hr, drill_complete, sum24Hr. **Keep raw strings** (no casting, no cleaning) so the placeholders are visible. Report row count, wellbore count, duplicate wellbore/date pairs. Then diff against `volve_ddr_master` row by row (on filename) and explain every difference.

**3. Data quality.** Reproduce Table 1 (population by column); count the '-999.99' and '0' depth placeholders and the literal "None" narratives; run the Unicode survey (½, ¼, ¾, ⅛: DDR counts and occurrences); and find date sentinels (e.g. 1980-01-01).

**4. Classify.** First prove the port is faithful: run the ported v3 on the old `volve_ddr_master` narratives and reproduce 1,303 classified, with per-phase counts identical to the old table. Only then run it on the new extraction and reproduce Table 2. Write out the priority order and hole-size rules as a paper-ready table (open item 3).

**5. Timeline dataset.** Exclude the placeholders and cast depth; write `outputs/timeline.csv` (wellbore, date, days_from_first_ddr, md_m, phase, filename).

**6. Audit.** Assign the eleven descriptive categories to unclassified records. Exclude EMPTY_RECORD (the "None" narratives). **TJ decision 2026-10-24 (see `notes/decisions.md`): keep the existing 50-record sample and the original stratification; do not redraw and do not apply the 1980 stratum fix.** Strata stay as in v2 (construction era = date_report within 730 days of the wellbore's first DDR, sentinel included; 296 + 87, allocation 39 + 11). Load the old 50 from `inputs/old_audit/audit_adjudicated.csv` (copy the adjudications, don't retype them) and map each record to its filename by wellbore + date. Verify the mapping is one-to-one against the new extraction, and report any record that does not map or whose narrative text differs. Rebuild the frame and strata from the new extraction and report whether they still give 383 / 296 + 87. The 15/9-19 A 1980-sentinel and 15/9-F-1 2013 re-entry stratum misassignments are reported as a stated limitation, not fixed. Then compute: sample proportion, Wilson 95% CI, scale by **frame size / total DDRs** (not unclassified / total), stratum-weighted check, and the floor from EMPTY_RECORD.

**7. NOD validation.** TD comparison for all wellbores, with the technical-sidetrack matching rule (WITSML T2 wellbore to NOD parent designation; abandoned parent legs reported as unmatched). Spud comparison across WITSML field, first-DDR free text and NOD entry date, with the tolerances TJ sets (open item 5; ask before computing).

**8. Kick-off recovery.** One row per sidetrack by designation: method (free text / depth sequence / none), depth, evidence quote, confidence. Resolve open item 2 (the 15th sidetrack). Resolve open item 1: list every 15/9-F-1 C DDR with md and the first 300 characters of its narrative, and state whether any report before 2014-03-13 shows depth shallower than 3,059 m. **Do not interpret beyond the evidence; flag it for TJ**, because it affects other papers.

**9. Duration table** (only if TJ says go): per wellbore, first and last DDR, days to TD, days in each phase.

**10. Figures.** Regenerate Figs 1–4 from `outputs/` at 300 dpi, with consistent phase colours. Every figure script reads only from `outputs/`.

**11. Registry.** Write `outputs/numbers_registry.json`: one entry per number in the manuscript (id, value, description, producing script and function, input file hashes, timestamp). Then do a full comparison against `inputs/numbers_registry.json` and the v2 targets below.

**12. Manuscript.** Update a copy of the v2 docx so every number matches the registry. Write `manuscript/CHANGES.md` listing each changed number (old, new, registry id, reason). Clear the yellow [TJ: ...] notes that the rerun resolved, and list the ones still open. No em dashes.

**13. Publish.** Write the README (how to reproduce end to end), LICENCE, and data licence note, and check that the repo matches the paper's Code and Data Availability statement. Open a PR from `rerun-2026-10`; TJ merges.
